# 블로그 채널 운영 구성

## 현재 활성 프로필 5개

설정의 `발행 채널`과 발행 보조에서는 다음 다섯 프로필만 활성 표시한다.

1. `생활자료` · Blogger · 파란색
   - 생활 제도, 지원금, 건강 상식, 교통, 소비자 정보, 주거·금융 기초
2. `IT 사용법` · Blogger · 파란색
   - Windows, PC, 스마트폰, 앱, AI 서비스, 전자기기, 인터넷 서비스
3. `요즘 화제` · Blogger · 파란색
   - 스포츠, 방송·콘텐츠, 인물, 사건, 국내외 이슈와 검색 급증 주제
4. `네이버 국내 장소·서비스·경험` · 네이버 블로그 · 녹색
   - 국내 장소·서비스, 직접 경험과 사진이 필요한 글, Blogger 성과 글의 네이버식 재구성
5. 기존 연결을 우선하는 티스토리 프로필 1개 · 주황색
   - 관리형 자동 추천 전략이 아니라 실제 연결과 사용자 수동 선택을 위한 프로필로 유지한다.

Blogger 3개와 네이버 1개는 글감 추천에 사용하는 관리형 전략 4개다. 티스토리 1개를 포함한 실제 연결 프로필 수는 5개이므로 `추천 전략 4개`와 `활성 프로필 5개`를 같은 개념으로 보지 않는다.

## 설정 화면 배치

설정 메뉴에 들어가면 `기본 설정`이 먼저 열린다. 상단 메뉴는 다음 순서로 표시한다.

- `기본 설정`
- `AI·품질`
- `발행 채널`
- `자동화·이력`
- `데이터·연동`

`발행 채널`에서는 실제 블로그 프로필 연결 탭을 운영 규칙보다 위에 표시한다. 플랫폼은 Blogger 파란색, 네이버 녹색, 티스토리 주황색으로 구분한다.

## 기존 설치의 프로필 정리

설정의 발행 채널 또는 발행 보조를 열면 고정 5개 구성을 동기화한다.

- Blogger 관리형 프로필 3개와 네이버 관리형 프로필 1개를 준비한다.
- 티스토리 프로필이 여러 개면 실제 글쓰기 주소가 저장된 프로필을 우선하고, 그다음 활성·기본 여부와 최근 수정 시각을 고려해 1개를 선택한다.
- 티스토리 프로필이 없으면 기본 티스토리 프로필 1개를 추가한다.
- 기존 네이버 프로필에 실제 연결 주소가 있고 새 네이버 고정 프로필이 기본 주소뿐이면 로그인·글쓰기 주소와 출력 기본값을 승계한다.
- WordPress, Velog, 브런치, 사용자 지정과 중복 Blogger·네이버·티스토리 프로필은 활성 목록과 발행처 선택에서 제외한다.

제외 프로필은 물리 삭제하지 않는다. `is_active = FALSE`로 보관하여 과거 초안 배정, 발행 준비, Blogger 바인딩과 발행 기록의 프로필 참조를 유지한다. 기존 기록의 프로필 ID를 새 프로필로 자동 치환하지 않는다.

## 연결 정보 관리

고정 5개 프로필에서는 다음 정보만 수정한다.

- 프로필 이름
- 로그인 페이지 주소
- 글쓰기 페이지 주소
- 기본 출력 형식
- 기본 카테고리와 태그
- 발행 보조 기본 선택 여부

플랫폼 종류는 고정한다. 일반 설정 화면에서는 새 프로필 추가, 숨긴 프로필 복원, 플랫폼 변경 기능을 제공하지 않는다.

## Blogger 연결과 발행

세 Blogger 프로필은 각각 다른 실제 Blogger 블로그에 연결한다. OAuth 클라이언트와 토큰은 프로젝트 보호 파일로 유지하고 저장소·안전 ZIP·로그에 포함하지 않는다.

프로그램은 Blogger 공식 API로 비공개 초안만 만든다. 최종 공개는 Blogger 화면에서 사용자가 수행하며 같은 초안·프로필·내용의 재전송은 기존 멱등성 기록으로 중복 API 호출을 막는다.

## 운영 안전 기준

- 세 Blogger 모두에 보조 Google 계정을 관리자로 등록한다.
- `content-trend-tracker`에 원문, 출처, 리비전과 사실 확인 기록을 보존한다.
- Blogger 콘텐츠는 정기적으로 공식 백업하고 테마 변경 직후 테마도 별도 백업한다.
- 비상용 빈 Blogger를 미리 운영하지 않고 문제가 생기면 새 Blogger를 만든 뒤 검증된 글부터 선별 복원한다.
- `요즘 화제`는 순위·경기 결과·일정·환율·날씨 등 시점 의존 사실 자료가 없으면 AI 요청서를 만들지 않는 기존 차단 규칙을 유지한다.
- 자동 로그인, 쿠키 저장, CAPTCHA 우회와 무인 자동 게시를 추가하지 않는다.

## 티스토리 글쓰기 연결과 5단계 흐름

- 티스토리 프로필에는 개인 블로그 홈 주소만 입력한다.
- 프로그램은 해당 주소에서 `/manage/newpost` 새 글 편집기 주소를 자동 생성한다.
- 발행 보조는 `준비 저장 → 전달 데이터 복사 → 글쓰기 화면 열기 → 확장 진단·입력 → 직접 확인` 순서로 진행한다.
- 별도 로그인 열기는 정상 흐름에 노출하지 않고 로그인 오류 도움말 안에서만 제공한다.
- 확장은 게시·임시저장 버튼을 누르지 않으며 최종 저장과 발행은 사용자가 수행한다.

## 플랫폼별 연결 주소와 필수 단계와 선택 도구

- Blogger와 네이버는 실제 새 글 화면을 연 뒤 주소창의 편집기 주소를 프로필에 저장한다.
- 티스토리는 개인 블로그 홈 주소에서 `/manage/newpost`를 생성한다.
- 발행 보조 색상은 Blogger 파랑, 네이버 초록, 티스토리 주황을 유지한다.
- `준비값 확인·변경한 경우 저장`은 조건부다.
- `전달 데이터 복사`, `글쓰기 편집기 열기`, `확장에서 불러오기·진단·입력`, `직접 확인 후 저장·발행`은 필수다.
- 개별 복사·미리보기·호환성 검사와 Blogger API 비공개 초안은 선택 영역에 둔다.
- 자동 로그인, 쿠키 저장, CAPTCHA 우회, 게시 버튼 자동 클릭은 추가하지 않는다.

## 연결 준비도 진단

- 설정의 발행 채널 화면은 고정 프로필 5개의 전체 연결 수와 플랫폼별 완료 수를 표시한다.
- 상태는 `연결 완료`, `연결 필요`, `주소 확인 필요`로 구분한다.
- Blogger와 네이버의 일반 홈 주소는 연결 완료로 보지 않고 실제 새 글 편집기 주소가 필요하다.
- 티스토리 일반 포털 주소는 연결 완료로 보지 않고 개인 블로그 홈 주소가 필요하다.
- 발행 보조는 선택 프로필이 준비되지 않았으면 글쓰기 버튼보다 설정 경로를 먼저 안내한다.
- 연결 준비도 진단은 저장된 주소 형식만 읽기 전용으로 확인하며 외부 접속·로그인·쿠키 확인을 수행하지 않는다.
- 연결 준비 완료는 실제 브라우저 이동 성공을 보증하지 않는다. 다음 실사용 검증에서 플랫폼별로 확인한다.
