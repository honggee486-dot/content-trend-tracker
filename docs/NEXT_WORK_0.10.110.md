# 0.10.110 다음 작업 — 감독형 반자동 콘텐츠 제작

## 2026-08-22 우선순위 갱신

최우선 목표는 추천 글감을 고른 뒤 **기존 글쓰기 → Luna High 품질 감사 → 기존 작성 모델 최소 수정 → 최종 사실 검증 → 이미지 자동 처리 → 블로그 발행 준비**까지 이어지는 감독형 흐름을 실제 사용 가능한 수준으로 완성하는 것이다.

장기 목표와 안전 경계는 `docs/CONTENT_SUPERVISOR_TARGET.md`를 기준으로 한다.

정상 목표:

```text
추천 글감
→ 1순위 주제 방향 기본 선택
→ 자동/수동 작성 선택
→ 기존 작성 경로로 1차 글
→ 기본 JSON·출처 검사
→ Luna High 텍스트 감사
→ 필요 시 기존 작성 모델 1회 최소 수정
→ 최종 출처·사실·JSON 검사
→ 최종 텍스트 확정
→ 이미지 전략 재계획·자동 획득
→ 블로그 배정·발행 준비
→ 사용자 최종 확인
```

자동 로그인, 쿠키·세션 수집, CAPTCHA 우회, 사용자 승인 없는 최종 공개 게시,
비용이 발생할 수 있는 AI 모델의 자동 사용은 추가하지 않는다.

## 현재 1순위 — 글쓰기 실행을 실제 cycle에 연결

자동/수동 작성 선택을 실제 1차 글 생성에 연결한다.

자동 작성:

1. 안전하게 사용할 수 있는 구독형 실행 경로가 확인되면 우선 사용
2. 사용할 수 없거나 실패하면 저장된 0원 API 1~4순위
3. 각 호출 직전 0원 여부 재확인
4. 첫 정상 응답에서 즉시 종료
5. 네 후보 모두 실패하면 요청서와 자료팩을 보존하고 수동 작성 상태로 전환
6. 정상 응답은 기존 parser와 출처 검사를 통과해야 다음 단계로 진행

수동 작성:

- 기존 ChatGPT 전달·JSON 가져오기 흐름 보존
- 특정 모델명을 schema에 고정하지 않음

완료 조건:

- 자동/수동 어느 경로든 동일한 유효한 1차 `ParseResult`를 다음 단계에 제공

## 다음 2순위 — Luna High 품질 감사 통합

1차 결과가 기본 검사에 통과하면 이미지 정보를 제외한 텍스트만 Luna High에 1회 전달한다.

Luna 역할:

- 직접 재작성 금지
- 문제 탐지
- `revision_requests`
- `keep_points`
- 새 사실·출처 임의 생성 금지

`pass`면 바로 최종 사실 확인으로 진행한다.

`revision_needed`면 기존 작성 모델에:

`원고 + revision_requests + keep_points`

를 전달해 필요한 부분만 1회 수정한다.

Luna를 자동 작성 모델 1~4순위에 섞지 않는다.

상세 계약은 `docs/CONTENT_QUALITY_REVIEW.md`를 따른다.

## 다음 3순위 — 최종 사실 확인·초안 저장

Luna 이후의 최종 텍스트를 기준으로 처리한다.

1. 수정 결과를 기존 AI JSON parser로 검사
2. 최종 본문 기준 `fact_checks`·sources 재검증
3. 공식 근거가 직접 뒷받침하지 않는 강한 표현은 삭제·완화
4. 해결되지 않은 핵심 사실은 사용자 확인 또는 안전한 보류 상태
5. 유효한 결과만 generation session/draft로 저장
6. 실패 시 요청서·원래 1차 결과·Luna 감사 결과를 보존

Luna `pass` 자체를 fact-check 통과로 간주하지 않는다.

## 다음 4순위 — 최종 텍스트 기준 이미지 처리

이미지는 Luna와 최종 사실 확인 뒤 처리한다.

1. 과거 1차 image 계획을 최종 실행 계약으로 사용하지 않음
2. 최종 문단·소제목 위치를 기준으로 이미지 필요 여부 재판정
3. 공식 근거 화면이면 `official_capture`
4. 대표/설명 이미지면 현재 0원 생성 경로
5. 명확한 상업 이용 무료 자산이 더 적합하면 `verified_free`
6. 의미가 없으면 이미지 없음
7. 획득 후 crop·resize·overlay·provenance
8. 최종 본문 위치와 draft/publish 패키지에 연결

공공·공식 사이트도 모든 사진을 자유 재사용 가능하다고 간주하지 않는다.
표·통계·조건·공식 UI처럼 설명에 직접 필요한 근거 영역을 우선한다.

## 실사용 검증

자동화 계층을 연결한 뒤 실제 정보성 글을 플랫폼별 최소 1편씩 처리한다.

### Blogger

- 전체 감독 흐름으로 글 1편
- 제목·본문·이미지·링크·라벨·미리보기
- 가능한 공식 임시저장/발행 준비 범위
- 진행을 막는 문제는 다음 플랫폼 전에 수정

### Tistory

- 다른 실제 글감 1편
- 카테고리·태그·본문 서식·이미지·링크·미리보기
- 공통 문제와 플랫폼 고유 문제 분리

### Naver Blog

- 다른 실제 글감 1편
- 태그·검색/공개 설정·편집기 입력·이미지·미리보기
- 자동 임시저장 지원이 부족하면 사용자 최종 저장 단계만 남김

## 실사용 사실 확인 품질

- 최종 `fact_checks`는 마지막 사실 감사 결과
- `verified`는 실제 source_ids가 주장 전체를 직접 뒷받침할 때만 사용
- 정책·금융의 시행일·소득·자산·금액·대상은 공식 자료 우선
- 확인되지 않은 비핵심 주장은 삭제·완화
- 기존 저장 결과는 강제 변환하지 않고 호환 처리

## 후순위

감독형 제작 흐름이 실사용 안정화되기 전에는 다음을 우선하지 않는다.

- GDELT
- Hacker News
- Bluesky
- 기타 새 트렌드 출처
- Google 유료 이미지 생성
- 이미지 overlay 템플릿 다변화
- 새 Provider 추가
- 다중 Agent 오케스트레이션
- 미래 가능성만을 위한 대규모 자동화 Framework

## 완료 조건

- 추천 주제·방향·작성 방식 선택 뒤 1차 글이 만들어짐
- 자동 작성 성공 시 수동 복사/붙여넣기가 필요 없음
- Luna High가 텍스트를 1회 감사함
- 필요한 경우 기존 작성 모델이 수정 요청만 1회 반영함
- 최종 텍스트가 다시 출처·사실·JSON 검사를 통과함
- 최종 글 기준 이미지가 자동 준비됨
- 적합한 블로그가 자동 배정됨
- 플랫폼별 안전한 임시저장 또는 편집기 준비 상태까지 진행됨
- 사용자는 최종 결과를 보고 발행·수정·삭제·보류에 집중함
- 자동 로그인·쿠키 저장·CAPTCHA 우회·무인 최종 공개가 없음
- 유료 AI 모델이 자동 호출되지 않음
