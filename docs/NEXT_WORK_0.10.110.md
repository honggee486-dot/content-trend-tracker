# 0.10.110 다음 작업 — 감독형 반자동 콘텐츠 제작

## 2026-08-22 우선순위 갱신

현재 최우선 목표는 사용자가 제작 화면을 단계별로 반복 조작하는 구조에서 벗어나,
**대시보드에서 추천 글감과 주제 방향을 고르고 자동/수동 작성 방식을 선택한 뒤 프로그램이 검증된 초안을 발행 준비까지 넘기는 감독형 반자동 흐름**을 완성하는 것이다.

상세 장기 목표와 안전 경계는 `docs/CONTENT_SUPERVISOR_TARGET.md`를 기준으로 한다.

정상 목표 흐름:

```text
추천 글감 대시보드
→ 주제 선택
→ 검증 점수 1순위 주제 방향 기본 선택
→ 자동/수동 작성 추천 확인 및 사용자 override
→ AI 요청서 생성
→ 자동 작성 또는 기존 수동 ChatGPT 흐름
→ 기존 JSON 형식·출처 검사
→ 검증된 초안 저장
→ 적합한 블로그 배정
→ 공식 지원 범위의 임시저장 또는 안전한 편집기 준비
→ 사용자 최종 확인
→ 발행 / 수정 / 삭제·보류
```

자동 로그인, 쿠키·세션 수집, CAPTCHA 우회, 사용자 승인 없는 최종 공개 게시,
실제 비용이 발생할 수 있는 AI 모델의 자동 사용은 추가하지 않는다.

## 현재 완료된 기반

- 트렌드 수집·정규화·군집·글감 평가와 추천/검토 후보 흐름
- Gemini 주제 방향 3개 생성과 검증 점수 기반 정렬
- 검증 점수 1순위 방향을 화면과 AI 요청서의 기본 방향으로 사용하는 흐름
- AI 요청서 → AI JSON 검사 → 초안 → 사실 확인 → 발행 보조 흐름
- 콘텐츠 작업 대기열과 블로그 추천/배정 기반
- 자동 작성용 현재 0원 모델 카탈로그와 1시간 lazy refresh
- 모델 성능 데이터 24시간 lazy refresh
- 사용자가 저장한 0원 API 1~4순위 fallback 설정
- 자동 작성 호출 직전 0원 여부 재확인 계약
- 주제 방향 생성과 함께 `auto` / `manual` 작성 추천을 저장하는 계약
- 판정이 없거나 애매한 기존 자료는 `manual`로 안전하게 처리

## 현재 1순위 — 자동 작성 실행 계층 연결

다음 응집 작업은 AI 요청서 화면의 자동/수동 선택을 실제 실행 흐름에 연결하는 것이다.

### 자동 작성

1. 사용자가 `자동 작성`을 선택한다.
2. 공식 ChatGPT 계정 인증을 사용하는 Codex/Agent 실행 경로가 현재 환경에서 안전하게 사용 가능한지 로컬 계약을 먼저 확인한다.
3. 프로그램은 브라우저 로그인 데이터·쿠키·세션 토큰을 직접 읽거나 저장하지 않는다.
4. 구독형 Agent가 사용 가능하면 이를 우선 사용한다.
5. Agent 사용 불가·한도 소진·일시 실패이면 저장된 0원 API 1~4순위를 순서대로 시도한다.
6. 각 API 호출 직전에 현재 비용이 0원인지 다시 확인한다.
7. 첫 정상 응답에서 즉시 fallback을 종료한다.
8. 네 후보가 모두 실패하면 요청서와 자료팩을 보존한 채 수동 작성으로 종료한다.
9. 자동 응답도 기존 AI 결과 parser와 출처 검사를 그대로 통과해야 한다.
10. 검사 통과 결과만 기존 generation session과 draft 흐름으로 저장한다.

### 수동 작성

- 현재 `ChatGPT에서 요청하기 → 사용자가 답변 JSON 복사 → AI 결과 가져오기` 흐름을 그대로 보존한다.
- 특정 ChatGPT 모델명을 UI 계약이나 저장 데이터에 고정하지 않는다.
- 자동 추천이더라도 사용자는 수동을 선택할 수 있고, 수동 추천이더라도 경고를 확인한 뒤 자동을 선택할 수 있다.

## 다음 2순위 — 자동 검사·초안 저장

자동 생성 결과를 받은 뒤 사용자가 별도 화면으로 이동해 붙여넣지 않아도 다음을 수행하도록 연결한다.

1. 형식·출처 검사
2. 검사 실패 원인 분류
3. 복구 가능한 JSON 형식 오류만 제한적으로 재시도
4. 사실 근거 부족은 모델을 무한 교체하지 않고 재검색·주장 완화·수동 확인 상태로 전환
5. 유효한 결과만 generation session 저장
6. 기존 draft 생성 로직 재사용
7. 실패 시 요청서·자료팩·기존 초안 보존

## 다음 3순위 — 단일 감독 대시보드 정리

기존 `콘텐츠 작업 대기열`과 추천 글감 화면을 재사용해 사용자가 여러 제작 화면을 찾아다니지 않게 한다.

대시보드에서 최소한 다음을 한 흐름으로 확인·선택할 수 있게 한다.

- 추천 글감과 주요 근거
- 추천 블로그
- 주제 방향 3개와 1순위 기본 선택
- 자동/수동 작성 추천과 이유
- 현재 제작 상태
- 자동 작성 성공/실패와 실제 사용 Provider/모델
- 사실 확인 또는 사용자 판단이 필요한 예외
- 발행 준비 완료 초안

새로운 대시보드를 별도로 중복 구현하기보다 현재 `콘텐츠 작업 대기열`과 `오늘의 트렌드` 화면을 우선 확장한다.

## 다음 4순위 — 블로그별 임시저장·발행 준비

자동 작성과 검증된 로컬 초안 저장이 안정된 뒤 Blogger → Tistory → Naver Blog 순으로 실제 플랫폼 연결을 검증한다.

원칙:

- 플랫폼 공식 API 또는 공식적으로 허용된 방식이 실제 임시저장을 지원할 때만 자동 임시저장을 구현한다.
- 지원 여부가 불명확하면 비공개 작성 API를 추측해 호출하지 않는다.
- 공식 임시저장이 불가능한 플랫폼은 제목·본문·태그·카테고리·이미지·링크를 편집기에 옮기기 쉬운 상태까지 준비한다.
- 로그인과 최종 공개 판단은 사용자가 직접 한다.
- 프로그램은 최종 공개 버튼을 자동으로 누르지 않는다.

## 플랫폼 실사용 검증

자동화 계층이 연결된 뒤 실제 정보성 글을 플랫폼별 최소 1편씩 처리한다.

### Blogger

- 전체 감독 흐름으로 글 1편을 준비한다.
- 가능한 임시저장/발행 준비 수준을 실제 공식 기능 기준으로 확인한다.
- 제목·본문·이미지·링크·라벨·미리보기 문제를 기록한다.
- 진행을 막는 문제가 있으면 다음 플랫폼 전에 수정한다.

### Tistory

- Blogger 흐름 안정 후 다른 실제 글감으로 1편을 처리한다.
- 카테고리·태그·본문 서식·이미지·링크·미리보기 차이를 확인한다.
- 플랫폼 고유 문제와 공통 문제를 분리한다.

### Naver Blog

- 앞의 두 플랫폼이 안정된 뒤 다른 실제 글감으로 1편을 처리한다.
- 태그·공개/검색 설정·편집기 입력·미리보기 차이를 확인한다.
- 공식 자동 임시저장 범위가 부족하면 사용자 최종 저장 단계를 명확히 남긴다.

## 실사용에서 확인된 사실 확인 품질 규칙

- 최종 `fact_checks`는 `나중에 확인할 항목` 목록이 아니라 마지막 사실 감사 결과로 취급한다.
- 공식·신뢰 가능한 출처가 주장 전체를 직접 뒷받침하면 `verified`와 실제 `source_ids`를 사용한다.
- `needs_verification`은 요청서가 요구하는 재검증 뒤에도 필요한 일부를 확정할 수 없는 경우에만 남긴다.
- 정책·금융의 시행일·소득·자산·금액·대상 같은 핵심 조건은 공식 기관 자료를 우선한다.
- 끝내 확인되지 않은 비핵심 주장은 본문에서 제거하거나 완화한다.
- 기존 저장 요청서 원문은 강제로 변환하지 않고 최신 화면·검증 계약으로 호환한다.

## 무료 외부 트렌드 신호 후보 — 자동 제작 흐름 안정화 후 검토

새 트렌드 출처 확장은 현재 자동 제작·검증·발행 준비보다 우선하지 않는다.

1. **GDELT** — 글로벌 뉴스 확산 신호를 소규모로 검증
2. **Hacker News 공식 API** — AI·개발·스타트업 기술 신호에 한정
3. **Bluesky 공개 API/Jetstream** — 다른 출처와 함께 나타날 때만 소셜 보조 신호로 검토

Mastodon Trends, OpenAlex, GitHub REST 검색/이벤트는 현재 후순위로 유지한다.
여러 source를 한 번에 추가하지 않고 비용 0원·노이즈·중복·운영 부담을 하나씩 검증한다.

자동 제작 흐름이 안정된 뒤 실제 반복 불편이 확인될 때만 검토한다.

- Data Source Capability / Fallback Matrix

- 장시간 작업 재시작/복구 강화
- 의미 있는 변화 감지와 후속 확인

## 완료 조건

장기 목표가 실사용 가능한 수준에 도달하려면 다음을 만족해야 한다.

- 사용자가 대시보드의 추천 목록에서 주제를 선택할 수 있음
- 검증 점수 1순위 주제 방향이 기본 선택되고 다른 방향으로 변경 가능
- 자동/수동 작성 추천과 이유가 보이며 사용자가 반대로 선택 가능
- 자동 작성 성공 시 수동 복사/붙여넣기 없이 기존 검사·초안 저장으로 이어짐
- 자동 작성 실패 시 데이터 손실 없이 수동 작성으로 전환 가능
- 적합한 블로그가 자동 배정됨
- 플랫폼별 안전한 임시저장 또는 편집기 준비 상태까지 자동 진행됨
- 사용자는 최종 글을 확인해 발행·수정·삭제·보류에 집중함
- 자동 로그인·쿠키 저장·CAPTCHA 우회·무인 최종 공개가 없음
- 유료 AI 모델이 자동으로 호출되지 않음
