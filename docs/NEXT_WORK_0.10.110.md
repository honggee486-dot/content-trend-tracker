# 0.10.110 다음 작업 — 콘텐츠 기회 레이더 + 감독형 제작

## 2026-08-22 방향 갱신

프로젝트의 중심 목표를 다음처럼 잡는다.

> **이미 많이 나온 트렌드를 뒤늦게 정리하는 도구**가 아니라,
> **앞으로 검색될 가능성이 높고 아직 공급이 부족한 정보성 소재를 조기에 찾고, 검증된 글까지 완성하는 도구**로 발전시킨다.

기존 수집·군집·주제 방향·작성·검수·이미지·발행 보조 기능은 버리지 않고 재사용한다.
새 핵심은 글쓰기 앞단에 **콘텐츠 기회 레이더**를 추가하고, 화면을 운영 콘솔 형태로 재구성하는 것이다.

정상 목표:

```text
외부 신호 수집
→ 시간별 관측·확산 추적
→ 수요 / 공급 / 포화도 / 예상 수명 계산
→ 콘텐츠 기회 Watchlist
→ 🔥 급상승 / 🟠 초기 신호 / 🟢 정보성 기회 / ⚪ 포화·종료
→ 예상 검색 의도 생성·검증
→ 작성 가치가 있는 소재만 기존 글감 흐름으로 승격
→ 주제 방향·작성 방식 선택
→ 기존 작성 모델 1차 글
→ 기본 JSON·출처 검사
→ Luna High 텍스트 감사 1회
→ 필요 시 기존 작성 모델 1회 최소 수정
→ 최종 출처·사실·JSON 검사
→ 최종 텍스트 확정
→ 이미지 전략 재계획·자동 획득
→ 블로그 배정·발행 준비
→ 사용자 최종 확인
```

자동 로그인, 쿠키·세션 수집, CAPTCHA 우회, 사용자 승인 없는 최종 공개 게시,
비용이 발생할 수 있는 AI 모델의 자동 사용은 추가하지 않는다.

## 개발 순서

앞으로의 기본 순서는 다음과 같다.

### 1. 현재 자동작성 / Luna / 이미지 실행 기반 검증

현재 이미 존재하는 기반을 먼저 깨끗하게 검증 가능한 상태로 만든다.

- 자동/수동 작성 추천과 0원 자동 작성 모델 fallback
- Luna High 텍스트 감사와 1회 최소 수정 계약
- 최종 텍스트 뒤 이미지 재계획 원칙
- 대표 이미지 생성 기반
- 공개 공식 페이지 격리 캡처 executor
- 관련 workflow 하네스 선택 누락 보완
- 하네스에서 실제 외부 API와 브라우저 스모크를 강제로 비활성화

하네스 통과는 실제 Chrome/Edge나 실제 외부 모델 호출 성공을 뜻하지 않는다.
실환경 검증은 필요한 단계에서 별도로 수행한다.

### 2. 콘텐츠 기회 레이더 데이터 계약

다음 값이 시간에 따라 누적·재계산될 수 있는 계약을 만든다.

- `first_seen`
- `last_seen`
- 관측 이력
- `velocity`
- `acceleration`
- 수요 점수
- 공급 점수
- `saturation`
- `expected_lifetime`
- 출처별 최초 포착 시각과 확산 순서

단순 총량보다 **증가 속도와 공급 부족**을 더 중요하게 본다.

같은 외부 ID·URL 재수집 때 기존 원문 행을 무한 추가하지 않는 현재 멱등성 계약을 유지한다.
관측 이력은 원문 게시 시각을 재수집 시각으로 덮어쓰지 않는다.

### 3. Watchlist + 상태 판정

화면과 내부 계약의 기본 상태는 다음 네 개로 한다.

- 🔥 **급상승** — 몇 시간 안에 판단해야 하는 소재
- 🟠 **초기 신호** — 아직 작지만 증가 속도가 높아 계속 관찰할 소재
- 🟢 **정보성 기회** — 폭발적이지 않아도 검색 수요 대비 좋은 정보성 콘텐츠가 부족한 소재
- ⚪ **포화/종료** — 이미 콘텐츠가 많거나 관심이 꺾인 소재

상태와 행동은 분리한다.

예:

```text
🔥 급상승      → 지금 작성
🟠 초기 신호   → 계속 관찰
🟢 정보성 기회 → 지금 작성
⚪ 포화/종료   → 종료
```

상태를 이모지 장식이 아니라 사용자가 즉시 판별하는 운영 배지로 사용한다.

### 4. 예상 검색 의도 생성·검증

사건·키워드 자체를 그대로 글 제목으로 쓰는 데서 끝내지 않는다.

현재 신호를 바탕으로 사람들이 곧 검색할 가능성이 있는 정보성 질문을 만든다.

예:

```text
정책 발표
→ 대상은?
→ 언제부터?
→ 신청방법은?
→ 소득·자산 기준은?
→ 필요한 서류는?
→ 기존 제도와 무엇이 다른가?
```

AI는 질문 후보를 만들 수 있지만 실제 글감 승격은 현재 신호·공식 자료·검색 근거로 다시 검증한다.
새 사실·수치·출처를 추측해 만들지 않는다.

검색 의도와 SEO 구조는 고정 공식보다 **현재 공개 검색 결과의 실측 근거**를 우선한다.

- 대상 플랫폼의 현재 검색 결과에서 상위 문서가 공통으로 다루는 하위 질문, 빠진 질문, 게시 시점·신선도와 화면에서 확인 가능한 이미지·영상·문서 구조를 필요한 범위에서 측정한다.
- 과거 특정 시점의 글자 수·이미지 수·키워드 반복 횟수 같은 표본값을 전역 규칙으로 고정하지 않는다. 기존 값과 현재 측정값이 다르면 현재 근거를 우선한다.
- 검색어, 측정 시각, 공통 요소, 콘텐츠 공백을 근거로 남겨 왜 해당 검색 의도·글 구조를 선택했는지 추적 가능하게 한다.
- 자동 로그인·쿠키·개인 세션 없이 공개적으로 확인 가능한 범위만 사용하고, 검색 결과 접근이나 표본 신뢰도가 부족하면 `검증 필요`로 남긴다.

### 5. 기존 글감 승격 흐름에 연결

콘텐츠 기회 레이더에서 작성 가치가 확인된 소재만 기존 군집·글감·주제 방향 파이프라인으로 넘긴다.

기본 판단 요소:

- 관심 증가 속도
- 관심 가속도
- 여러 출처의 동시·순차 확산
- 실제 검색 의도
- 최근 콘텐츠 공급 증가량
- 포화도
- 예상 수명
- 사실 근거 확보 가능성

이미 많은 콘텐츠가 존재하고 상승세가 꺾인 소재는 높은 절대 관심도만으로 자동 추천하지 않는다.

### 6. 전체 UI 구조 개편

2~5번 기능과 함께 하나의 큰 기능 묶음으로 진행한다.

기본 화면 구조:

```text
좌측 고정 메뉴
→ 페이지별 상단 미니 대시보드
→ 필터·빠른 액션
→ 상세 목록/작업 영역
→ 필요 시 접힌 로그·진단 영역
```

좌측 메뉴는 작업 단계 기준으로 정리한다.

예상 메뉴:

- 대시보드
- 기회 레이더
- 트렌드·군집
- 글감·주제 방향
- 작성
- 검수
- 이미지
- 발행 준비
- 로그·진단
- 설정

상단 미니 대시보드에는 현재 페이지에서 바로 판단해야 할 핵심 수치만 표시한다.
기회 레이더 화면에서는 최소 다음 카드를 둔다.

```text
🔥 급상승
🟠 초기 신호
🟢 정보성 기회
⚪ 포화/종료
```

상세 목록에는 가능한 범위에서:

- 소재
- 상태
- 수요 속도
- 공급량
- 포화도
- 예상 수명
- 추천 검색 의도
- 권장 행동

을 표시한다.

기존 상단 메뉴·세로 나열 UI는 단계적으로 운영 콘솔형 구조로 바꾸되 기존 기능을 먼저 보존한다.

### 7. 자동 작성 → Luna → 최종 검증

콘텐츠 기회 레이더에서 승격된 글감은 기존 제작 흐름을 사용한다.

자동 작성:

1. 안전하게 사용할 수 있는 구독형 실행 경로가 실제로 확인되면 사용
2. 불가·실패 시 저장된 0원 API 1~4순위
3. 호출 직전 0원 여부 재확인
4. 정상 응답은 기존 parser와 출처 검사를 통과해야 다음 단계로 진행
5. 모두 실패하면 요청서와 자료팩을 보존하고 수동 작성으로 전환

Luna High:

- 글을 직접 다시 쓰지 않음
- 사진·이미지는 검토하지 않음
- `revision_requests`와 `keep_points`만 생성
- 정상 케이스 한 편당 1회
- `revision_needed`일 때 기존 작성 모델 수정도 최대 1회

Luna 이후 최종 텍스트를 다시 parser·sources·fact_checks로 검증하고 나서 텍스트를 확정한다.

### 8. 이미지 자동 처리

이미지는 최종 텍스트 확정 뒤 처리한다.

우선순위:

1. 공식 근거 화면이 직접 유용함 → `official_capture`
2. 대표·설명 이미지가 적합함 → 현재 0원 생성 경로
3. 상업 이용 조건이 명확한 무료 자산이 더 적합함 → `verified_free`
4. 의미가 없으면 이미지 없음

1차 글쓰기 중의 임시 image 계획을 최종 실행 계획으로 사용하지 않는다.
공식 사이트의 사진·인물·홍보 자산을 자동으로 자유 재사용 가능하다고 간주하지 않는다.

공식 캡처에 강조·주석·개인정보 가림이 필요해지면 **원본 캡처와 가공본을 분리**한다. 강조 위치는 DOM/semantic region의 실제 bounding box 또는 이미지 픽셀 근거로 계산하고 눈대중 좌표로 확정하지 않는다. 대상 영역이 모호하면 자동 주석하지 않고 `manual_review`로 전환하며, 개인정보·식별정보 가림은 실제 영역을 기준으로 적용한 뒤 대표 프레임과 최종 표시 크기에서 다시 검수한다.

설명형 이미지에서 생성형 그림보다 텍스트·수치·레이아웃 정확성이 더 중요하면 HTML/CSS 기반의 결정론적 설명 카드도 후속 후보로 검토한다. 현재 `official_capture / 생성 이미지 / verified_free / 이미지 없음` 계약을 먼저 유지하고, 실제 필요가 확인되기 전에는 새 image 상태나 schema를 미리 추가하지 않는다.

### 9. 블로그 발행 준비

텍스트·이미지가 안정된 뒤:

1. Blogger
2. Tistory
3. Naver Blog

순으로 실제 지원 범위를 검증한다.

플랫폼별 요청서·발행 준비에는 **Google·Naver 등 검색 유입을 고려해 작성한다는 요구를 명시**하되, 하나의 SEO 공식을 모든 플랫폼에 강제하지 않는다. Naver는 당시 공개 검색 결과와 공식 가이드에 맞추고, Blogger/Tistory는 Google 검색 의도와 제목·소제목·요약·FAQ 등 실제 검색 친화 구조를 당시 근거로 검증한다.

공식 임시저장을 지원할 때만 자동 임시저장하고,
그렇지 않으면 제목·본문·태그·카테고리·이미지·링크를 편집기에 옮기기 쉬운 준비 상태까지 만든다.
로그인과 최종 공개 판단은 사용자에게 남긴다.

### 10. 실제 글로 전체 E2E 검증

실제 정보성 글을 플랫폼별 최소 1편씩 처리해 전체 감독 흐름을 검증한다.

- Blogger 1편
- Tistory 1편
- Naver Blog 1편

공통 문제와 플랫폼 고유 문제를 분리하고, 앞 플랫폼에서 발견된 공통 문제는 다음 플랫폼 전에 수정한다.

## 2~6번은 하나의 큰 기능 묶음

`콘텐츠 기회 레이더 데이터 계약 → Watchlist → 상태 판정 → 예상 검색 의도 → 기존 글감 승격 → 운영 콘솔 UI`는 서로 따로 완성하지 않는다.

데이터를 저장했는데 화면에서 판단할 수 없거나,
UI만 바꾸고 실제 상태 판정이 없는 반쪽 구현을 피한다.

다만 작업·검증·롤백이 어려워질 정도로 커지면 내부 구현은 응집된 세부 commit으로 나눌 수 있다.
최종적으로는 2~6번 전체가 연결된 하나의 사용자 기능으로 동작해야 한다.

## 현재 완료된 기반

현재 저장소에는 다음 기반이 있다.

- YouTube/NAVER/Daum/Google Trends/Wikimedia 수집·정규화
- 2단계 군집과 통합 순위
- 글감 평가·추천/검토 후보
- Gemini 주제 방향 3개와 1순위 기본 선택
- `auto` / `manual` 작성 추천과 사용자 override
- AI 요청서 → AI JSON 검사 → draft → fact-check → 발행 보조
- 현재 0원 자동 작성 모델 카탈로그와 사용자 1~4순위
- 1시간 model catalog / 24시간 performance lazy refresh
- 호출 직전 0원 여부 재확인
- Luna High 감사용 텍스트 payload·검수 JSON·수정 요청·1회 수정 cycle 계약
- 공식 캡처 / 검증 무료 자산 / 생성 이미지 전략 기반
- 격리 Headless Chrome/Edge CDP 공개 페이지 캡처 executor 기반

콘텐츠 기회 레이더의 시간별 관측·상태·Watchlist·검색 의도·UI는 아직 후속 구현 대상이다.

## 완료 조건

- 프로그램이 단순 인기 총량보다 상승 속도·공급 부족·포화도·예상 수명을 구분함
- 관찰 소재가 Watchlist에서 시간에 따라 상태를 바꿀 수 있음
- 🔥/🟠/🟢/⚪ 상태가 화면에 일관된 배지로 표시됨
- 예상 검색 의도가 실제 근거와 함께 검증되고, 고정 SEO 공식이 아니라 현재 검색 결과의 측정 시각·공통 요소·콘텐츠 공백을 추적할 수 있음
- 작성 가치가 있는 소재만 기존 글감 파이프라인으로 승격됨
- 좌측 메뉴 + 상단 요약 + 상세 영역의 운영 콘솔 UI가 동작함
- 자동 작성 성공 시 수동 복사/붙여넣기가 필요 없음
- Luna High가 텍스트를 1회 감사하고 필요한 경우 기존 작성 모델이 1회 최소 수정함
- 최종 텍스트가 출처·사실·JSON 검사를 통과한 뒤에만 이미지가 준비됨
- 공식 캡처의 자동 강조·가림이 필요하면 측정된 좌표를 사용하고 원본 캡처와 가공본이 분리됨
- 적합한 블로그가 배정되고 플랫폼별 안전한 임시저장 또는 편집기 준비 상태까지 진행됨
- 사용자는 최종 결과를 보고 발행·수정·삭제·보류에 집중함
- 자동 로그인·쿠키 저장·CAPTCHA 우회·무인 최종 공개가 없음
- 유료 AI 모델이 자동 호출되지 않음
