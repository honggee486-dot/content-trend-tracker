# P1-B 제작 흐름 브라우저 회귀검증

## 현재 자동 검증

제작 흐름의 브라우저 회귀검증은 저장소에 포함된 `scripts/run_browser_regression.py`와 `.github/workflows/browser-regression.yml`로 재현한다.

- 환경: GitHub Actions Ubuntu, Python 3.12, Playwright headless Chromium
- 데이터: 시스템 임시 디렉터리에 복사한 저장소와 새로 만든 테스트 전용 DuckDB
- 비밀정보 보호: `.env*`, Streamlit secrets, OAuth·credential 파일을 격리 복사에서 제외하고 관련 인증 환경변수도 전달하지 않는다.
- 실제 사용자 DB, 외부 교환 파일, API 키와 외부 API는 사용하지 않는다.
- 원본 저장소의 `data` 디렉터리와 사용자 데이터는 열거나 수정하지 않는다.

관련 앱·제작 흐름이 바뀌면 Browser Regression workflow가 실행되며 다음 계약을 확인한다.

1. 격리 Streamlit 기동과 상태 응답
2. 테스트 주제·공식 참고 자료로 `AI 요청서 준비` 작업 대기열 생성
3. 작업 대기열의 `AI 요청서 만들기`로 실제 화면 이동
4. AI 요청서·AI 결과 가져오기·글 편집·발행 보조 반복 이동
5. 각 이동에서 페이지 제목 단일 렌더링과 Streamlit 예외 부재 확인
6. `VERSION`과 브라우저 제목 일치 확인
7. 새로고침과 브라우저 뒤로·앞으로 이동 후 정상 렌더링 확인
8. 종료 시 임시 Streamlit 프로세스와 임시 디렉터리 정리

2026-08-08 현재 누적 작업 브랜치에서 위 격리 Chromium 회귀검증을 실제 실행해 통과했다. 과거 일회성 검증 workflow에 있던 화면 문구 고정 검사는 제거하고, 제작 흐름과 무관한 안내 문구 변경이 브라우저 회귀검증을 깨뜨리지 않도록 했다. 문구 자체의 계약은 해당 정적·단위 테스트에서 검증한다.

## 남은 실제 로컬 표본 확인

자동 격리 검증은 실제 사용자 데이터의 상태 조합과 실제 supervisor 수명주기를 대신하지 않는다. 다음 항목은 실제 로컬 환경에서 필요할 때 읽기 중심으로 확인한다.

- 과거 자료팩 입력값 재사용 후 다른 주제로 이동
- 저장된 AI 원문 다시 열기
- 서로 다른 자료팩의 AI 결과 검사 반복
- `run_app.bat` supervisor에서 같은 이동을 반복한 뒤 종료·재기동 확인
- 실제 사용자 DB를 임의 수정하지 않는다.
