# 0.10.109 진단 신뢰성과 하네스 라우팅 안정화

- 릴리스 후보는 최신 `origin/main`을 직접 부모로 하는 단일 커밋으로 구성하고 최종 브랜치는 `behind 0`, `ahead 1` 상태를 유지합니다.
- 최신 데이터 수집 대시보드는 자동 정리 조건 확인과 실제 정리 실행을 구분하고, 정리가 필요한 경우 출처 저장 뒤 순위 준비 직전에 실행된 결과를 표시합니다. 전체 출처 실패와 기존 군집 작업으로 순위 재계산이 보류된 경우도 완료로 오인하지 않도록 별도 문구로 표시합니다.
- deterministic baseline 읽기 전용 진단은 재구성이나 비교가 불완전하면 일치·불일치 수치를 채택 근거처럼 노출하지 않고, 신뢰 가능한 표본에서는 현재 군집과 baseline의 대표 제목을 사람용 출력으로 직접 비교할 수 있게 합니다.
- 운영·P2 진단은 군집 품질 runtime의 동일 표본·baseline 결과를 재사용해 진단을 중복 실행하지 않고, 실제 DB를 변경하지 않는 읽기 전용 계약을 유지합니다.
- 개발 하네스는 Python의 시나리오 매핑을 단일 기준으로 사용하며 BAT·PowerShell 진입점은 이를 재사용합니다. `diagnostics` 시나리오는 운영 진단, NAVER·Daum 전체 범위 진단과 P2 통합 진단 진입점을 함께 검증합니다.
- 릴리스 대상은 `VERSION 0.10.109`, `CHANGELOG.md`, `AI_CONTEXT.md`, `docs/NEXT_WORK.md`, 이 릴리스 노트와 릴리스 문서 정합성 테스트를 실제 코드·검증 상태에 맞춥니다.
- DB 스키마·외부 API·인증·의존성 계약은 변경하지 않으며 `.env`, 실제 DB/WAL/잠금, Parquet, 로그, OAuth·쿠키·브라우저 인증 상태와 테스트·빌드 임시 산출물은 릴리스 대상에서 제외합니다.
- 자동 검증은 실제 사용자 DuckDB, 외부 API, Windows 작업 스케줄러와 실사용 브라우저 세션을 대체하지 않습니다. 릴리스 후 실제 수집 진행 이력과 deterministic baseline 제목 표본은 읽기 중심으로 별도 확인합니다.
