# Release Bootstrap 0.10.107

- 릴리스 후보는 최신 `origin/main`을 직접 부모로 하는 단일 커밋이어야 한다.
- 최종 릴리스 브랜치는 `behind 0`, `ahead 1` 상태여야 한다.
- 릴리스 커밋에는 `VERSION`, `CHANGELOG.md`, 이 문서와 `AI_CONTEXT.md` 정리를 함께 포함한다.
- 누적 변경은 Gemini 주제 방향 부분 응답의 누락·검증 탈락 ID 전용 1회 보강, 2단계 군집 희소 응답 계약 정합화, 결정론적 군집 baseline 읽기 전용 비교 진단, 로컬 TPM 대기와 공급자 제한 구분, 적용 도구·하네스 안전성, Public 공개 준비를 하나의 최종 스냅샷으로 정리한다.
- 기존 유효 Gemini 결과와 군집 저장 결과를 보존하고 불확실·충돌 후보를 자동 병합하지 않으며 실제 DB·사용자 기록과 수동 최종 발행 원칙을 유지한다.
- `.env`, 실제 DB/WAL/잠금, Parquet, 로그, OAuth·쿠키·브라우저 인증 상태와 테스트·빌드 임시 산출물은 릴리스 커밋에 포함하지 않는다.
- Public 공개 준비 검사는 Git 전체 이력과 PR audit refs를 포함해 별도로 수행하며, Gitleaks와 과거 인코딩 payload 검토가 완료된 상태에서만 공개 전환을 진행한다.
- 자동 검증은 실제 DB·외부 API·Windows 작업 스케줄러·실사용 브라우저 세션을 대체하지 않는다.
- 릴리스 후에는 실제 데이터 표본에서 주제 방향 부분 응답 보강, 군집 희소 응답·결정론 baseline 진단, throttle 분류와 앱 supervisor 생명주기를 우선 확인한다.
