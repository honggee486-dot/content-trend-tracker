# 0.10.108 수집 후 정리 안전성과 Public CI 보호

- 릴리스 후보는 최신 `origin/main`을 직접 부모로 하는 단일 커밋으로 구성하고 최종 브랜치는 `behind 0`, `ahead 1` 상태를 유지합니다.
- 자동 정리는 새 출처 수집 전에 실행하지 않고 사용 가능한 출처 저장이 끝난 뒤 순위 준비 직전에 실행해 실패 수집이 기존 보존 자료를 먼저 줄이지 않도록 합니다.
- 모든 사용 가능한 출처가 실패하면 기존 통합 순위와 보존 자료를 유지하고 대기 중 자동 정리와 주제 방향 생성을 건너뜁니다. 일부 출처가 성공·부분 성공·변경 없음이면 해당 결과를 보존한 채 후속 순위 흐름을 계속합니다.
- 직접 실행, 예약/안전 실행, 대시보드 백그라운드 실행과 Streamlit 런타임이 동일한 `post_collection_cleanup_runtime` 계약을 사용하며 외부 API 대기 중 DuckDB 연결을 장시간 유지하지 않습니다.
- Public 저장소의 일반 CI에 현재 추적 트리 보호 경로 검사를 추가하되 기존 `workflow_dispatch`, `contents: read` 최소 권한과 모든 브랜치 push 검증 계약을 유지합니다.
- 릴리스 대상은 `VERSION 0.10.108`, `CHANGELOG.md`, `AI_CONTEXT.md`, `docs/NEXT_WORK.md`와 이 릴리스 노트를 실제 코드·테스트 상태에 맞춰 정리합니다.
- DB 스키마·외부 API 계약·의존성은 변경하지 않으며 `.env`, 실제 DB/WAL/잠금, Parquet, 로그, OAuth·쿠키·브라우저 인증 상태와 테스트·빌드 임시 산출물은 릴리스 대상에서 제외합니다.
- 자동 검증은 실제 DB·외부 API·Windows 작업 스케줄러와 실사용 브라우저 세션을 대체하지 않으며 릴리스 후 실제 수집 표본으로 운영 순서를 확인합니다.
