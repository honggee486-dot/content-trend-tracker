# 0.10.83 적용 도구 단일 커밋 안전 강화

## 변경 목적

검증된 작업 브랜치를 `main`에 반영하는 적용 도구가 프로젝트의 최종 커밋 정책과 정확히 일치하도록 안전 규칙을 강화했습니다. 최종 반영 브랜치는 현재 `origin/main`보다 뒤처진 커밋이 없고 정확히 한 커밋만 앞선 경우에만 적용할 수 있습니다.

## 주요 변경

- 자동 후보 목록은 `origin/main` 대비 `behind 0, ahead 1`인 `agent/` 브랜치만 표시합니다.
- 명령행으로 브랜치를 직접 지정해도 같은 조건을 강제합니다.
- `ahead 0`, `ahead 2 이상` 또는 `behind 1 이상`이면 검증과 `main` 반영 전에 명확한 오류로 중단합니다.
- 격리된 임시 worktree 검증을 마친 뒤 push 직전에도 원격 `main`, 작업 브랜치 SHA와 커밋 관계를 다시 확인합니다.
- `apply_update.bat`는 `pwsh.exe`가 있으면 PowerShell 7을 우선 사용합니다.
- PowerShell 7이 없으면 Windows PowerShell 5.1로 폴백합니다.
- BAT는 ASCII로 유지하며 `chcp 65001`과 상시 `pause`를 제거하고 PowerShell 종료 코드를 그대로 반환합니다.
- BAT는 실행 전에 자신을 시스템 임시 폴더로 복사하고, 안정된 임시 복사본에서 PowerShell 실행과 종료 처리를 수행합니다.
- 적용 과정에서 프로젝트의 원본 `apply_update.bat`가 새 커밋으로 교체되어도 실행 중인 BAT의 읽기 위치가 바뀌지 않습니다.
- 실제 `main` 반영은 성공했지만 원본 BAT 교체 뒤 `9009`를 반환하던 자기 교체 오류를 방지합니다.
- PowerShell 파서 테스트는 설치된 PowerShell 7과 Windows PowerShell 5.1을 각각 검사합니다.

## 유지한 안전 흐름

다음 기존 안전 검사는 변경하지 않았습니다.

1. 프로젝트 저장소·`origin`·현재 `main` 확인
2. 로컬 미커밋·미추적 변경 확인
3. 원격 기본 브랜치와 후보 브랜치 갱신
4. 보호·금지 파일과 공백 오류 검사
5. 별도 임시 worktree에서 Python 구문 검사와 전체 pytest 실행
6. 반영 직전 로컬·원격 SHA 재확인
7. 비강제 fast-forward 방식의 로컬 `main` 갱신과 일반 push
8. push 전 실패 시 로컬·원격 `main`과 사용자 파일 보존

강제 push, `reset --hard`, `git clean -fd`, 자동 stash와 충돌 자동 해결은 사용하지 않습니다.

## 호환성과 데이터 영향

- `scripts/apply_update.ps1`은 Windows PowerShell 5.1 호환 문법과 UTF-8 BOM을 유지합니다.
- DB 스키마, 설정 키, 콘텐츠 데이터와 외부 연동 계약은 변경하지 않습니다.
- 적용 대상 브랜치 조건만 더 엄격해졌으므로 기존 다중 커밋 작업 브랜치는 최신 `origin/main`에서 최종 파일 상태를 단일 커밋으로 다시 구성해야 합니다.
