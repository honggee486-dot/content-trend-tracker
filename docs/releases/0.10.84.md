# 0.10.84 Gemini 호출 실행 조건·종료 사유 기록

## 변경 목적

Gemini 호출이 끝난 뒤 요청량, 사고 수준, 제한 시간과 응답 종료 사유를 실제 호출 단위로 확인할 수 있도록 진단 기록을 보강했습니다. 로컬 운영 설정과 저장소 기본값이 다르더라도 당시의 유효 실행 조건을 기준으로 분석할 수 있습니다.

## 주요 변경

- 글감 분석 API 시도마다 실제 요청 본문에 포함된 글감 수와 당시 설정 상한을 기록합니다.
- 각 시도에 실제 전달한 `minimal`·`low`·`medium`·`high` 사고 수준과 HTTP 제한 시간을 기록합니다.
- HTTP 200 응답의 첫 후보에서 Gemini `finishReason`과 선택적 `finishMessage`를 저장합니다.
- `MAX_TOKENS` 종료 횟수를 일반 `response_validation_error`와 별도로 집계합니다.
- 안정성 패널에 실제 요청 수 평균·최대, 사고 수준별 호출 수, 종료 사유별 호출 수와 토큰 한도 종료 횟수를 표시합니다.
- 기존 Gemini 호출 이력 표에 실제 요청 수, 설정 상한, 사고 수준, 제한 시간과 종료 사유를 추가합니다.
- 비정상적으로 긴 종료 메시지는 기존 오류 메시지와 같은 1,000자 상한으로 저장합니다.

## DB 호환성

기존 `gemini_api_calls`에 다음 추가형 컬럼을 더합니다.

- `requested_item_count INTEGER`
- `configured_items_per_request INTEGER`
- `thinking_level VARCHAR`
- `request_timeout_seconds INTEGER`
- `finish_reason VARCHAR`
- `finish_message VARCHAR`

마이그레이션은 `CREATE TABLE IF NOT EXISTS`와 누락 컬럼별 `ALTER TABLE ADD COLUMN`만 사용합니다. 기존 호출에는 새 값이 없거나 종료 사유가 빈 문자열일 수 있으며, 기존 컬럼만 지정하는 INSERT도 계속 허용합니다.

## 유지한 동작

- 외부 Gemini API 호출 수와 요청 내용은 변경하지 않습니다.
- 프롬프트, 응답 JSON 스키마, 요청당 처리량과 재시도 정책은 변경하지 않습니다.
- 저장소 기본값 요청당 30개·사고 수준 `medium`은 유지합니다.
- 유효한 일부 결과 저장, 누락 항목 재처리와 `cluster_id` 연결을 유지합니다.
- Gemini 실패가 출처 수집 성공을 취소하지 않는 규칙과 직접 초안 생성 기능을 유지합니다.
- 기존 DB·자료팩·초안·리비전·사실 확인·발행 기록을 보존합니다.
