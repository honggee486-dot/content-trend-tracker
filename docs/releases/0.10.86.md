# 0.10.86 주제 방향 수요 근거·점수 계약

## 변경 목적

Gemini가 반환한 주제 방향의 배열 순서를 그대로 신뢰하던 구조를 보완했습니다. 검색 의도와 실제 독자 질문, 입력 신호에서 확인되는 수요 근거를 방향별로 연결하고, 검증된 하위 점수의 합계로 프로그램이 순서를 안정적으로 결정합니다.

## 주요 변경

- 각 원문 신호에 요청 안에서만 유효한 `E1`~`E8` 근거 ID를 부여합니다.
- 원문 URL과 내부 DB ID는 Gemini 요청에 넣지 않고, 제목·발행처·출처 유형·시각과 기존 DB에 있는 발견 검색어, 키워드, 포착 횟수, 신호값과 선택적 조회 지표만 전달합니다.
- 방향마다 다음 정보를 생성·검증·저장합니다.
  - `search_intent`: 독자가 검색하는 목적
  - `reader_question`: 독자가 실제로 해결하려는 질문
  - `demand_evidence`: 입력 신호에서 확인되는 수요 근거
  - `evidence_source_ids`: 요청 근거 ID와 연결된 원본 항목 ID
  - `score_breakdown`: 검색 의도 35점, 수요 신호 30점, 근거 가용성 20점, 차별성 10점, 시의성·실용성 5점
  - `score_reasons`: 점수 판단 이유
- 모델이 총점을 직접 반환하지 않습니다. Python이 검증된 하위 점수를 합산하고 총점 내림차순으로 안정 정렬하며, 동점이면 Gemini의 원래 순서를 유지합니다.
- 요청에 없는 근거 ID와 점수 범위를 벗어난 응답은 저장하지 않습니다.
- 최종 1순위 방향을 기준으로 `primary_direction_reason`을 다시 구성합니다.
- 화면에서 순위·총점·검색 의도·독자 질문·수요 근거와 점수 이유를 확인할 수 있습니다.
- 선택한 방향의 구조화된 정보가 AI 요청서 관점 입력까지 전달됩니다.

## 운영 기본값

- 새 설치의 Gemini 글감 분석 기본 처리량: 요청당 15개
- 허용 상한: 요청당 30개 유지
- 기본 동시 요청: 1개
- 새 DB의 자동 수집 기본 간격: 180분
- 기존 `.env`, 기존 DB의 저장 설정과 이미 등록된 Windows 작업은 자동 변경하지 않습니다.
- 주제 방향 생성의 Google 검색은 계속 비활성화합니다.

## DB 호환성

기존 `trend_cluster_ai_angles`에 다음 컬럼을 추가형으로 더합니다.

- `search_intent VARCHAR`
- `reader_question VARCHAR`
- `demand_evidence_json VARCHAR`
- `evidence_source_ids_json VARCHAR`
- `score_breakdown_json VARCHAR`
- `direction_score DOUBLE`
- `score_reasons_json VARCHAR`

기존 방향 데이터는 삭제하거나 일괄 재생성하지 않습니다. 과거 행은 새 값이 없는 상태로 계속 조회·표시되며, 완성된 기존 프로필을 버전 번호만으로 다시 Gemini에 보내지 않습니다.
