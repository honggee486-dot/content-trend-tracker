# 0.10.105 운영 안정성과 주제 방향 가시성

## 핵심 변경

### 관리형 Streamlit 실행

- 앱 주소를 `http://127.0.0.1:8518`로 고정했습니다.
- `run_app.bat`은 현재 터미널의 전경 supervisor를 실행하고 supervisor가 Streamlit 자식 프로세스를 소유합니다.
- 이름 있는 mutex로 같은 프로젝트의 중복 supervisor를 차단합니다.
- 포트가 이미 사용 중이면 임의 포트로 이동하지 않고 점유 PID를 표시한 뒤 중단합니다.
- 웹 업데이트 뒤에도 기존 supervisor가 같은 포트로 앱을 다시 시작하므로 원래 Antigravity 터미널이 생명주기를 계속 소유합니다.
- `stop_app.bat`은 등록된 프로젝트 경로·PID·프로세스 시작 시각을 확인해 해당 supervisor와 Streamlit만 종료합니다. 다른 Python·Streamlit 프로젝트를 일괄 종료하지 않습니다.

### 최신 데이터 수집 진행 화면

- 최신 데이터 수집을 별도 프로세스로 실행하고 공유 상태 파일로 진행률·현재 단계·단계 이력을 갱신합니다.
- 실행 현황은 진행 중 자동 펼침, 종료 후 자동 접힘으로 표시하며 최신 단계가 위에 나타납니다.
- 진행 중에는 수집·순위 재계산·주제 방향 버튼을 비활성화하고 종료 뒤 다시 활성화합니다.
- 화면의 게이지만이 아니라 실행 이력과 버튼 상태도 주기적으로 다시 평가합니다.

### 수집·군집·주제 방향 로그

- 출처 수집, 1차 군집, 2차 Gemini 군집, 통합 순위 계산·저장과 주제 방향 생성을 프로그램 로그에서 구분했습니다.
- 출처 수집이 완료된 뒤 후속 군집·순위 처리에서 오류가 발생해도 완료된 출처를 실패로 다시 표시하지 않습니다.
- 한 계산 안에서 중복된 `cluster_id`와 원문 연결을 저장 전에 정리해 기본키 충돌이 전체 저장을 취소하지 않도록 했습니다.

### 주제 방향 부분 성공과 대상 상세

- 이번 실행에서 일부 군집이 정상 저장되면 전체 미처리 원문이 남아 있어도 현재 저장된 군집의 주제 방향 생성을 이어갑니다.
- 남은 군집 미처리는 다음 실행 대상으로 유지합니다.
- 한 글감마다 방향 3개를 저장하므로 `글감 3개·방향 9개`처럼 서로 다른 수치를 명확히 구분합니다.
- 새 `주제 방향 대상 선정 상세` 로그는 다음 흐름을 한 행에 표시합니다.

```text
전체 군집
→ 추천·검토 상태
→ 기회 점수 기준 통과
→ 기존 방향 완료 제외
→ 생성 필요
→ 이번 확인 범위
→ 민감 제목 제외
→ 근거 없음 제외
→ 이번 생성 대상
→ 요청 범위 밖 미검사
```

- 이 집계는 읽기 전용이며 집계 실패가 기존 Gemini 생성이나 출처 수집 성공을 취소하지 않습니다.

### 잠금 복구 안전성

- 수집·군집 잠금에 프로세스 시작 식별자를 추가해 Windows PID 재사용을 구분합니다.
- heartbeat와 lease를 추가해 중단된 장시간 작업의 잠금이 영구 차단으로 남을 위험을 줄였습니다.
- 기존 형식 잠금은 PID 생존 확인만 사용하는 하위 호환 경로를 유지합니다.
- 시작 식별자를 읽지 못하면 정상 작업을 잘못 삭제하지 않도록 보수적으로 활성 상태를 유지합니다.
- 잠금 해제는 기존과 동일하게 token이 일치하는 소유자만 수행합니다.

## 데이터 호환성과 안전

- DuckDB 테이블·컬럼을 삭제하거나 기존 상태 의미를 변경하지 않습니다.
- 기존 원본, 군집, 주제, 자료팩, AI 응답, 초안, 리비전, 사실 확인과 발행 기록을 보존합니다.
- 한 출처나 Gemini 후처리 실패가 다른 출처의 정상 결과를 취소하지 않습니다.
- 외부 API 대기 중 DuckDB 연결을 장시간 유지하지 않습니다.
- 자동 로그인, 쿠키 저장, CAPTCHA 우회와 무인 자동 게시를 추가하지 않습니다.

## 적용 후 확인

1. `run_app.bat`이 8518에서 실행되고 중복 실행을 차단하는지 확인합니다.
2. 터미널 `Ctrl+C`와 `stop_app.bat`이 등록된 앱만 종료하는지 확인합니다.
3. 웹 업데이트 뒤 같은 터미널에서 8518 앱이 다시 시작되는지 확인합니다.
4. 수집 진행 중 실행 현황·버튼·프로그램 로그가 갱신되는지 확인합니다.
5. 주제 방향 실행 뒤 `주제 방향 대상 선정 상세`의 단계별 수량이 실제 생성 대상 수를 설명하는지 확인합니다.
6. 장시간 수집·군집 중 heartbeat가 갱신되고 정상 종료 뒤 잠금이 해제되는지 확인합니다.

## 검증 상태

누적 작업 브랜치 적용 과정에서 이전 변경 범위는 Python 구문 검사와 텍스트 위생 검사를 통과했고, 마지막 확인 당시 전체 pytest는 테스트 계약 문구 한 건을 제외한 `921 passed`였습니다. 해당 테스트 계약은 실제 재실행 명령과 사용자 안내 문구를 구분하도록 수정했습니다.

이번 릴리스 최종 브랜치는 `apply_update.bat`의 격리된 Python 구문 검사·텍스트 위생 검사·전체 pytest를 다시 통과한 뒤에만 `main`에 반영해야 합니다. GitHub 연결 환경에서는 실제 Windows `Ctrl+C`, 포트 해제, 웹 업데이트 재시작, 실제 DuckDB와 외부 Gemini 호출을 실행하지 않았습니다.
