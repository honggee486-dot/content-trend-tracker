# 0.10.103 1차 정리·Flash-Lite 2차 군집화

## 처리 흐름

1. 최근 분석 범위에서 아직 현재 군집 엔진으로 완료되지 않은 원문을 최신순으로 최대 4,000개 읽습니다.
2. 같은 정규 URL을 먼저 묶고, 날짜·회차·제품·방향 충돌이 없는 안전한 완전 동일 제목을 다음으로 묶어 1차 군집을 만듭니다.
3. 1차 군집을 요청당 최대 200개씩 `gemini-3.5-flash-lite`에 보내 같은 구체적 사건인지 2차 분류합니다.
4. 앞선 배치에서 처리 완료된 2차 군집 후보가 있으면 새 1차 군집만 그 군집에 연결할 수 있습니다. 기존 2차 군집끼리는 자동 병합하지 않습니다.
5. 이번 시험은 백그라운드 작업 한 번당 최대 5회로 제한해 최대 약 1,000개의 1차 군집을 처리합니다.

새 Gemini 기능 ID는 `trend_cluster_grouping_v3`입니다. 요청 문자 상한 때문에 실제 배치가 200개보다 작아질 수 있으며 실제 처리량과 토큰은 배치 로그에 남습니다.

## DB 연결과 백그라운드 실행

- 수동 `저장 자료 정리·순위 다시 계산`은 별도 Python 프로세스를 시작하고 Streamlit 화면은 즉시 반환합니다.
- 후보와 기존 군집을 읽은 뒤 DuckDB 연결을 닫습니다.
- Gemini 요청과 순위 점수 계산 동안 DuckDB 연결을 유지하지 않습니다.
- 각 배치 결과가 완성된 뒤에만 짧은 트랜잭션으로 군집·처리 이력·로그를 반영합니다.
- `data/trend_clustering.lock`은 수집 잠금과 별개로 중복 군집 작업만 막습니다.

## 부분 성공과 안전장치

- 같은 URL이어도 날짜·회차·제품·금액·주가 상승·하락 같은 명백한 사실이 충돌하면 1차 군집을 분리합니다.
- Gemini가 반환한 기존 군집 ID는 프로그램이 제공한 후보 목록에 있을 때만 허용합니다.
- 불확실·누락 후보는 `retry`로 남기고 세 번째에도 확정되지 않으면 `needs_review`로 전환합니다.
- API 키가 없거나 전체 호출이 실패하면 정상 AI 경로의 유사도 의미 군집은 실행하지 않습니다. 순위 표시는 분리된 비상 결정론적 폴백으로 유지하되 AI 처리 완료로 기록하지 않아 다음 실행의 재검토 대상은 보존합니다.
- 완료된 2차 군집만 이후 배치의 기존 군집 후보로 사용합니다.

## 기록과 데이터 보존

- `trend_cluster_processing`에 입력 해시·1차 군집 키·결과 군집·상태·시도 횟수를 기록합니다.
- `trend_clustering_jobs`와 `trend_clustering_job_batches`에 검색 미처리 수, URL 중복 절감, URL 충돌 분리, 동일 제목 병합, 실제 요청·대기 1차 군집, 기존 연결·새 군집·불확실·충돌, 시간과 입력/출력/사고/전체 토큰을 기록합니다. 화면은 완료 1차 군집 1,000개당 예상 토큰도 표시합니다.
- `topics`, `topic_source_links`, 자료팩, AI 요청서·응답, 초안, 리비전, 사실 확인과 발행 기록은 자동 수정하지 않습니다.
