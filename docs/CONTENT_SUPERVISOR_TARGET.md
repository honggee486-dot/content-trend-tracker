# 콘텐츠 감독형 반자동 제작 목표

## 목표

`content-trend-tracker`의 장기 사용 방식은 사용자가 제작 단계를 반복 조작하는 도구가 아니라,
프로그램이 수집·분석·작성·검수·사실 확인·이미지 준비·발행 준비를 대부분 수행하고
사용자는 핵심 선택과 최종 공개 판단에 집중하는 **감독형 반자동 콘텐츠 제작 시스템**으로 한다.

정상 흐름:

```text
대시보드
→ 추천 글감 선택
→ 검증 점수 1순위 주제 방향 기본 선택
→ 자동/수동 작성 추천 확인 및 필요 시 변경
→ 기존 작성 경로로 1차 글 작성
→ 기본 JSON·출처 검사
→ Luna High 텍스트 품질 감사 1회
→ 필요 시 기존 작성 모델이 Luna 수정 요청만 반영
→ 최종 출처·사실·JSON 검사
→ 최종 텍스트 확정
→ 최종 글 기준 이미지 전략 재계획
→ 공식 화면 캡처 / 0원 생성 / 검증 무료 자산 / 이미지 없음
→ 이미지 후처리·본문 배치
→ 대상 블로그 자동 배정
→ 플랫폼별 임시저장 또는 안전한 편집기 준비
→ 사용자 최종 확인
→ 발행 / 수정 / 삭제·보류
```

## 사용자가 맡는 일

정상 케이스의 반복 작업은 다음을 중심으로 줄인다.

1. 추천 글감 중 실제로 쓸 주제 선택
2. 기본 1순위 주제 방향을 그대로 쓰거나 변경
3. 자동/수동 작성 추천을 그대로 쓰거나 변경
4. 준비된 최종 글과 이미지를 확인해 발행·수정·삭제·보류

자료 수집, 정규화, 군집, 글감 평가, 근거 정리, 기본 방향 선정, 요청서 작성,
1차 결과 검사, Luna 감사, 수정 요청 전달, 최종 사실 확인, 이미지 획득,
초안 저장, 블로그 배정과 플랫폼별 준비는 가능한 범위에서 프로그램이 처리한다.

## 자동화 경계

자동화 수준을 높여도 다음을 유지한다.

- 자동 로그인 금지
- 브라우저 쿠키·세션 토큰·기존 프로필 직접 수집/저장 금지
- CAPTCHA 우회 금지
- 사용자 승인 없는 최종 공개 게시 금지
- 실제 비용이 발생할 수 있는 AI 모델의 자동 사용 금지
- 플랫폼이 공식 지원하지 않는 비공개 작성 API 추측 사용 금지
- 실제 DB·Secret·개인 데이터 보호

플랫폼별 임시저장은 공식 API 또는 현재 프로젝트의 안전한 사용자 보조 방식으로 가능할 때만 자동화한다.
지원되지 않으면 편집기 입력 준비까지 자동화하고 최종 저장/공개는 사용자가 수행한다.

## 단계별 구현 순서

### 1. 감독 의사결정 계층

- 주제 방향 3개 생성
- 검증 점수 1순위 기본 선택
- `auto` / `manual` 작성 추천과 이유 저장
- 사용자가 방향·작성 방식을 override 가능

### 2. 기존 글쓰기 실행 계층

자동 작성:

- 공식적으로 허용된 구독형 실행 경로가 안전하게 사용 가능하면 우선 검토
- 불가·한도·일시 실패 시 저장된 0원 API 1~4순위를 사용
- 각 외부 호출 직전 0원 여부 재확인
- 첫 정상 응답에서 종료
- 모두 실패하면 요청서·자료팩을 보존하고 수동 흐름으로 전환

수동 작성:

- 기존 `ChatGPT에서 요청하기 → JSON 가져오기` 흐름 보존
- 특정 모델명을 저장 schema나 UI 필수 계약으로 고정하지 않음

### 3. 기본 결과 검사

- 수동/자동 모두 같은 기존 AI JSON parser와 출처 검사를 사용
- 기본 형식·출처 계약을 통과한 텍스트만 품질 감사로 전달
- 실패 원인을 보존하고 데이터 손실 없이 복구 가능 상태 유지

### 4. Luna High 품질 감사

- 사진·캡처·thumbnail은 제외
- Luna는 작성자가 아니라 감사자
- 원고를 직접 다시 쓰지 않고 `revision_requests`와 `keep_points`만 반환
- 새 사실·출처를 지어내지 않음
- 정상 케이스 글 한 편당 1회만 감사

상세 계약은 `docs/CONTENT_QUALITY_REVIEW.md`를 따른다.

### 5. 기존 작성 모델 최소 수정

- Luna가 `pass`면 작성 모델을 다시 호출하지 않음
- `revision_needed`면 원래 작성 경로에 수정 요청을 전달
- 문제가 없는 부분과 `keep_points`는 유지
- 필요한 부분만 수정
- 수정 호출도 정상 케이스 최대 1회
- 수정 과정에서는 이미지 block을 만들지 않음

### 6. 최종 출처·사실·JSON 검사

- Luna 감사 결과 자체를 사실 검증으로 취급하지 않음
- 최종 수정된 문장을 대상으로 fact_checks와 sources를 다시 확인
- 확인된 근거보다 강한 주장은 완화·삭제
- 유효한 최종 텍스트만 이후 이미지 단계로 넘김

### 7. 최종 이미지 계층

이미지 계획은 최종 텍스트 확정 뒤 다시 만든다.

우선순위:

1. 공식 화면 자체가 사실 근거에 유용함 → `official_capture`
2. 대표/설명용 이미지가 적합함 → 0원 생성 이미지
3. 라이선스가 명확한 무료 자산이 더 적합함 → `verified_free`
4. 이미지가 의미 있게 기여하지 않음 → 이미지 없음

1차 글쓰기 중 만들어진 image 계획은 최종 실행 계약으로 사용하지 않는다.

### 8. 블로그별 발행 준비

- 블로그 추천·배정 결과 재사용
- Blogger → Tistory → Naver Blog 순으로 실제 지원 범위 검증
- 공식 임시저장 지원 시에만 자동 임시저장
- 아니면 제목·본문·태그·이미지·링크를 안전한 편집기 입력 준비 상태로 만듦
- 최종 공개는 사용자

### 9. 감독 대시보드 통합

새 대시보드를 중복 구현하기보다 기존 작업 대기열·추천 글감 화면을 확장한다.

최소 표시:

- 추천 글감·주요 근거
- 추천 블로그
- 주제 방향과 현재 선택
- 자동/수동 작성 추천
- 1차 작성 상태
- Luna 감사 결과
- 최종 사실 확인 상태
- 이미지 준비 상태
- 최종 발행 준비 초안

## 현재 구현 상태

현재 저장소에는 다음 기반이 있다.

- 트렌드 수집·군집·글감 후보와 추천 흐름
- Gemini 주제 방향과 1순위 기본 선택
- 자동/수동 작성 추천 계약
- AI 요청서 → AI JSON 검사 → draft → fact-check → 발행 보조
- 현재 0원 자동 작성 모델 카탈로그와 1~4순위 설정
- 1시간 model catalog / 24시간 performance lazy refresh
- 호출 직전 0원 여부 재확인 계약
- 공식 캡처 / 검증 무료 이미지 / 생성 이미지의 이미지 전략 기반

후속 구현은 실제 작성 executor 연결 → Luna 감사 통합 → 최종 사실 검증 → 이미지 실행 → 플랫폼 실사용 순으로 진행한다.

## 완료 기준

일반적인 글 한 편에서 다음이 성립해야 한다.

- 사용자가 여러 제작 화면을 순서대로 찾아다닐 필요가 없음
- 추천 주제·방향·작성 방식의 최소 선택만 하면 됨
- 자동 작성 성공 시 수동 복사/붙여넣기가 필요 없음
- 1차 글이 Luna 감사와 필요한 1회 수정 과정을 자동으로 통과함
- 최종 수정된 텍스트가 다시 출처·사실 검사를 통과함
- 이미지가 최종 글에 맞춰 다시 계획·준비됨
- 적절한 블로그 발행 준비 상태까지 자동 이동함
- 사용자는 최종 결과를 보고 발행·수정·삭제·보류 판단에 집중함
- 실패·비용·검증 불확실성은 안전한 상태로 전환되고 데이터가 보존됨
