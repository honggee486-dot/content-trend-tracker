# 트렌드 출처 검토 승격 정책

## 목적

YouTube, NAVER, Daum, Google Trends, Wikimedia 신호는 기존 군집 단계에서 모두 같은 최근 분석 스냅샷에 들어간다. 현재 2차 군집 런타임은 최대 50,000개 후보를 주제순으로 정렬하고 토큰 기준으로 나눠 비교하므로 출처별 강제 할당량이나 별도 군집 엔진을 추가하지 않는다.

이 문서는 서로 같은 주제로 묶였더라도 사실 원문이 부족하거나, 강한 단독 관심 신호로 남아서 기존 점수 정책상 `보류`가 되는 후보 중 사람이 검토할 가치가 있는 신호만 `검토`까지 올리는 계약을 기록한다.

## 원칙

- 기존 `추천` 조건은 완화하지 않는다.
- 새 정책은 `보류 → 검토`만 허용하며 `추천`으로 직접 올리지 않는다.
- `구체적 주제 확인 필요`, 섹션·홈페이지형 원문, 약한 단독 신호는 계속 `보류`한다.
- YouTube 단독은 구체적인 콘텐츠 제목과 충분한 품질·글감 기회가 있어야 하며, `ASMR`처럼 맥락 없는 단일 엔터티는 강한 조회 신호여도 승격하지 않는다.
- Google Trends·위키백과는 인물명·프로그램명·사건명 자체가 유효한 관심 키워드일 수 있으므로 entity-only라는 이유만으로 제외하지 않는다. 대신 단일 엔터티는 일반 제목보다 더 높은 관심 강도를 요구한다.
- Google Trends·위키백과 승격은 정식 어댑터가 저장한 `google_trend`·`wikipedia_pageview` 신호만 사용한다. 출처 이름만 같은 임의 데이터는 승격 근거로 쓰지 않는다.
- YouTube와 Google Trends·위키가 같은 군집에 있거나, 포털·커뮤니티 원문과 강한 트렌드 신호가 겹치면 단독 신호보다 낮은 개별 임계값으로 수동 검토할 수 있다.
- Google Trends·위키백과 신호는 관심도 근거이지 사실 근거가 아니다. 시점 의존 글의 사실 참고 자료 차단 계약은 그대로 유지한다.
- 출처별 상위 목록 할당량은 두지 않는다.
- 강한 트렌드 신호가 `검토`로 승격됐는데 기존 기사 중심 점수식 때문에 기본 목록에서 사라지지 않도록, 승격 후보에만 최대 50점 이하의 보수적인 트렌드 점수 하한을 적용한다. 이 보정은 `추천` 승격 조건에는 사용하지 않는다.
- 정책 버전은 순위 서명에 포함한다. 정책이 바뀌면 기존 순위를 재사용하지 않고 다음 계산에서 새 기준으로 다시 점수화한다.
- 정책·점수 규칙 변경으로 순위 서명만 달라지고 신규 미처리 원문이 0건이어도 백그라운드 군집 작업의 빠른 종료 전에 기존 군집을 재점수하고 새 서명을 저장한다. 선택 원문이 없는 이 경로에서는 Gemini 군집 호출을 만들지 않는다.

## 현재 승격 범위

- 강한 YouTube 단독 확산 신호
- 강한 Google Trends 단독 관심 신호
- 강한 위키백과 단독 관심 신호
- YouTube + Google Trends/위키 관심 신호의 동일 주제 교차 확인
- Google Trends + 위키백과 동일 주제 교차 확인
- NAVER/Daum/커뮤니티 원문 + 강한 YouTube/검색/위키 신호의 동일 군집

구체 임계값은 `src/services/trend_source_review_policy.py`의 순수 정책 함수가 단일 기준이며, 모든 실행 경로에는 `src/services/trend_source_review_runtime.py`가 동일 정책과 순위 서명 버전을 설치한다.

## 실제 데이터 근거

2026-08-12 실사용 DB 점검에서 최근 분석 범위에 YouTube 501건, Google Trends 174건, 위키백과 88건이 존재했지만 기존 기본 목록에는 NAVER·Daum만 노출됐다. 새 정책 1차 적용 뒤에도 강한 YouTube 후보 1건만 `검토`로 저장됐고, Google Trends의 `송영길`, `이재명 지지율`, 위키백과의 `트로이 전쟁` 등은 entity-only 차단 또는 과도한 단독 신호 임계값으로 `보류`에 남았다. 이 결과를 근거로 정책 v2를 조정했다.

이후 앱에서 순위 재계산을 실행해도 정책 버전 때문에 순위 서명이 달라진 상태에서 신규 미처리 원문이 0건이면 백그라운드 작업이 계산 전에 종료되어 마지막 계산 결과가 계속 표시될 수 있음을 확인했다. 따라서 정책 임계값을 더 완화하기 전에 순위 서명만 바뀐 재계산도 실제로 저장되도록 작업 런타임 계약을 보완했다.

## 실제 DB 노출 진단

실제 목록에서 특정 출처가 보이지 않을 때는 임계값을 다시 조정하기 전에 `run_trend_source_visibility_diagnostics.bat`를 사용한다. 이 진단은 실제 DuckDB를 `read_only=True`로 열고 실행 전후 DB·WAL 크기와 수정 시각을 비교해 무변경 여부를 확인한다.

출처별 집계는 `trend_lookback_hours`에 해당하는 최근 원문이 현재 `trend_cluster_items`에 연결된 군집만 대상으로 한다. 오래된 원문만 연결된 과거 군집이 남아 있어도 최근 수집 신호가 현재 군집에 연결된 것처럼 판단하지 않는다.

기본 실행은 앱의 실제 기본 후보 목록과 같은 `추천+검토`, 최소 트렌드 점수 `30`, `글감 추천순(opportunity)`, 최대 `100개` 조건을 `list_ranked_trends()`로 그대로 적용한다. 따라서 `추천·검토 + 점수 통과`까지만 된 후보와 실제 상위 100개 안에 표시되는 후보를 구분한다. 필요하면 CLI의 `--minimum-score`, `--display-limit`, `--sort-by`로 현재 화면 필터에 맞춰 읽기 전용 비교할 수 있다.

진단은 `최근 원문 → 최근 원문의 현재 군집 연결 → 추천/검토/보류 → 최소 점수 통과 → 실제 정렬·표시 한도 진입` 순서를 집계한다. 점수 기준 아래인지, 추천·검토지만 표시 한도 밖인지, 모두 보류인지, 최근 원문이 아직 현재 군집에 연결되지 않았는지를 서로 구분한다. 혼합 군집은 여러 출처에 중복 집계될 수 있으므로 출처별 군집 수를 서로 더해 전체 군집 수로 해석하지 않는다.

이 진단은 외부 API·Gemini·Windows Scheduler를 호출하지 않고 설정·원문·군집 상태를 수정하지 않는다. 실제 DB 진단 결과 없이 출처별 할당량을 추가하거나 승격 임계값을 더 완화하지 않는다.

## 검증

- 일반 군집 안전장치와 오병합 방어는 기존 테스트를 그대로 통과해야 한다.
- 강한 구체적 YouTube 단독 신호는 `검토`, 약한 신호와 일반·노이즈 제목은 `보류`여야 한다.
- 강한 Google Trends·위키백과의 단일 엔터티 관심 키워드는 `검토`할 수 있지만 약한 신호는 계속 `보류`여야 한다.
- 트렌드 출처끼리 교차 확인된 후보도 `추천`으로 직접 승격하면 안 된다.
- 승격 후보의 점수 하한은 50점을 넘지 않아야 한다.
- 정식 `signal_type`이 없는 Google Trends·위키 유사 데이터는 승격되지 않아야 한다.
- 신규 미처리 원문이 없는 `ready` 순위 준비 상태도 계산·최종화를 한 번 거쳐 새 순위 서명을 저장해야 하고, 이미 `reused` 상태이거나 실제 미처리 원문이 있으면 이 사전 재계산 경로를 타지 않아야 한다.
- 임시 DuckDB 통합 회귀에서는 강한 YouTube·Google Trends·위키백과 단독 신호가 실제 순위 재계산과 저장을 거친 뒤 `최소 점수 30 + 추천·검토` 목록에서 `검토`로 조회되고 해당 출처 카운트가 유지되어야 한다. 이 검사는 실제 사용자 DB를 사용하지 않는다.
- 출처별 노출 진단은 임시 DuckDB에서 기본 목록 표시·표시 한도 밖·점수 미달·최근 미군집을 구분하고, 오래된 군집을 최근 출처 노출로 오인하지 않으며 CLI 실행 전후 DB·WAL 상태가 바뀌지 않아야 한다.
- 실제 DB에서 새 순위를 다시 계산한 뒤 출처별 노출 비중을 재확인하고, 그 결과 없이 임계값을 추가로 완화하지 않는다.
