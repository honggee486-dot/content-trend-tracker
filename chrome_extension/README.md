# 콘텐츠 트렌드 트래커 Chrome 입력 보조

이 폴더는 `content-trend-tracker`의 발행 패키지를 사용자가 직접 로그인한
Chrome 블로그 편집기에 넣는 로컬 전용 Manifest V3 확장 프로그램입니다.

## 설치

1. Chrome 주소창에 `chrome://extensions`를 입력합니다.
2. 오른쪽 위 `개발자 모드`를 켭니다.
3. `압축해제된 확장 프로그램을 로드합니다`를 누릅니다.
4. 프로젝트의 `chrome_extension` 폴더를 선택합니다.
5. 확장 프로그램을 도구 모음에 고정합니다.

## 사용

1. 콘텐츠 트렌드 트래커의 `발행 보조`에서 초안과 발행처를 선택합니다.
2. `1단계 준비 내용 저장`으로 SEO·이미지 계획을 저장합니다.
3. `필수 ② 전달 데이터 복사`를 누릅니다.
4. 선택한 플랫폼 색상의 `필수 · 글쓰기 바로 열기` 버튼을 누릅니다.
5. 글쓰기 탭에서 확장 아이콘을 누르고 `클립보드에서 불러오기`를 실행합니다.
6. `입력칸 진단`으로 제목·본문·태그·검색 설명 후보와 iframe 위치를 확인합니다.
7. 이상이 없으면 `현재 편집기에 입력`을 누릅니다.
8. 제목·본문·태그·검색 설명과 이미지 3개 위치를 직접 확인합니다.
9. 미발견이나 오류가 있을 때만 `호환성 보고서 복사`를 사용합니다.
10. 임시저장 또는 발행은 사용자가 직접 수행합니다.

티스토리는 설정에서 개인 블로그 홈 주소만 저장하면 프로그램이 `/manage/newpost`를 자동으로 연결합니다. 로그인되어 있으면 바로 새 글 편집기로 이동하고, 로그인이 필요하면 로그인 후 글쓰기 버튼을 다시 누릅니다.

클립보드 접근이 차단되면 팝업의 전달 데이터 칸에 JSON을 직접 붙여넣은 뒤
`입력칸 진단`과 `현재 편집기에 입력`을 사용할 수 있습니다.

## 입력칸 진단

- 현재 문서와 접근 가능한 same-origin iframe을 재귀적으로 탐색합니다.
- 제목·본문·태그·검색 설명에 대응하는 선택자와 iframe 경로만 표시합니다.
- 입력칸의 현재 값, 작성 중인 원고, 로그인 정보는 읽거나 출력하지 않습니다.
- 접근할 수 없는 cross-origin iframe 수를 표시해 수동 보완이 필요한지 판단할 수 있게 합니다.
- 진단 결과가 `후보 발견`이어도 실제 에디터 상태 반영 여부는 입력 후 직접 확인해야 합니다.

## 호환성 보고서

입력칸 진단 또는 편집기 입력 후 팝업에서 JSON 보고서를 확인하고 복사할 수 있습니다.
플랫폼 편집기 선택자를 보강할 때 이 보고서를 사용합니다.

보고서에 포함되는 정보:

- 현재 탭의 호스트 이름
- 진단 또는 입력 동작 구분
- 감지된 편집기 유형
- 접근 가능한 문서와 접근 불가 iframe 수
- 제목·본문·태그·검색 설명의 선택자·iframe 경로·입력 성공 여부

보고서에 포함되지 않는 정보:

- 전달 데이터의 제목·본문·태그·이미지 메모
- 편집기에 이미 입력된 값과 작성 중인 원고
- URL 경로·쿼리·해시
- 로그인 ID·비밀번호·쿠키·브라우저 세션

## 안전 경계

- `activeTab`은 사용자가 확장 프로그램을 누른 현재 탭에만 사용합니다.
- 고정된 전체 사이트 접근 권한(`host_permissions`)을 요청하지 않습니다.
- 로그인 ID, 비밀번호, 쿠키, Chrome 프로필을 읽거나 저장하지 않습니다.
- 전달 데이터는 기본 10분 뒤 만료되며 체크섬이 일치해야 합니다.
- 확장 프로그램은 게시·임시저장 버튼을 누르지 않습니다.
- 이미지 파일은 자동 업로드하지 않고 3개 배치 안내만 전달합니다.
- 편집기 DOM이 바뀌면 일부 입력칸을 찾지 못할 수 있습니다. 진단 결과를 확인하고 수동 입력으로 보완하세요.

## 지원 범위

초기 지원 대상은 다음과 같습니다.

- 네이버 블로그
- 티스토리
- Google Blogger
- 사용자 지정 편집기의 일반적인 제목·본문·태그·설명 입력칸

플랫폼 편집기 구조가 바뀌면 `content.js`의 선택자만 최소 범위로 갱신합니다.

## 선택자 미발견 시 구조 후보

확장 버전 0.3.0부터 제목이나 본문 선택자를 찾지 못해도 보이는 입력 후보를 최대 40개까지 호환성 보고서에 포함합니다.

포함하는 정보는 HTML 태그, input type, id, name, role, placeholder, aria-label, data-placeholder, class 이름과 same-origin iframe 위치뿐입니다. 입력칸의 현재 값, `textContent`, `innerHTML`, URL 경로·쿼리·해시, 비밀번호 입력칸과 파일 입력칸은 읽거나 출력하지 않습니다.

프로그램의 `Chrome 호환성 보고서 검사`에 1.1 보고서를 붙여넣으면 구조 후보 표를 확인할 수 있습니다. 기존 1.0 보고서도 계속 검사할 수 있습니다.
